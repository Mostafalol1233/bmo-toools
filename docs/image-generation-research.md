# نتائج بحث مولد الصور المجاني

## المصدر الأول: Puter.js
الرابط: https://developer.puter.com/tutorials/free-unlimited-image-generation-api/

توضح الصفحة أن Puter.js يتيح استدعاء نماذج توليد صور من الواجهة الأمامية عبر `puter.ai.txt2img(prompt)`، وأن التطبيق لا يحتاج إلى إدارة مفتاح API خاص به. النموذج المعلن هو نموذج دفع المستخدم؛ أي إن كل مستخدم يصادق بحسابه في Puter ويتحمل استخدامه، لذلك لا يتحمل صاحب التطبيق تكلفة الذكاء الاصطناعي بحسب شرح الخدمة. كما تعرض الصفحة إمكانية إضافة المكتبة عبر حزمة npm أو عبر ملف CDN، وتذكر أن النماذج المتاحة قد تتغير.

## المصدر الثاني: التوثيق الرسمي لـ Puter
الرابط: https://docs.puter.com/AI/txt2img/

يعرّف التوثيق الدالة `puter.ai.txt2img()` بأنها دالة تستقبل وصفاً نصياً وتعيد صورة، وتدعم صيغ استدعاء بخيارات إضافية للنموذج والمزوّد، كما تشير الصفحة إلى وجود وضع اختباري لاستهلاك واجهة الاختبار دون استخدام أرصدة API. التوثيق يحتوي على أقسام مستقلة للمصادقة، وحدود الاستخدام، ونموذج دفع المستخدم، ولذلك لا ينبغي وصف الخدمة بأنها مجانية بلا حدود لكل مستخدم؛ الأفضل عرضها داخل BMO باعتبارها خياراً مجانياً مبدئياً يعتمد على سياسة Puter وتسجيل المستخدم عند طلب التوليد.

## القرار المقترح
المسار الأكثر ملاءمة للتجربة الأولى هو دمج Puter.js داخل صفحة مولد الصور من المتصفح، مع زر توليد واضح ورسالة تشرح أن الخدمة الخارجية قد تطلب تسجيل دخول أو تفرض حدوداً. يجب توفير حالة فشل ورسالة بديلة بدلاً من إعلان أن التوليد مضمون بلا تدخل. لا يُحفظ مفتاح سري داخل الواجهة، ولا تُرسل الصور إلى خادم BMO في هذا المسار.

## ملاحظة مهمة
الخدمات العامة الأخرى مثل Pollinations قد تتغير سياساتها أو تطلب مفتاحاً بحسب نقطة النهاية الحالية، لذلك لم يُعتمد عليها دون توثيق رسمي مباشر في هذه الجولة.
